ASSIGNMENT 7 - DIGITAL SIGNATURE USING DSA
============================================================

1. AIM
------
To generate a DSA key pair, sign a message using the private key, verify the signature
using the public key, test a modified message and test an incorrect public key.

2. DEFINITIONS
--------------
DSA:
Digital Signature Algorithm. A public-key algorithm for digital signatures.

Digital signature:
A cryptographic value created using a private key and checked using the corresponding
public key.

Signing:
Creating a signature with the private key.

Verification:
Checking the signature with the public key.

Authentication:
Checking the claimed origin of a message.

Integrity:
Checking that the signed message has not changed.

Non-repudiation:
A signature can provide evidence of origin, assuming the private key is controlled by
the signer and the key identity is properly established.

3. MATHEMATICAL FORMULAS
------------------------
Traditional DSA parameters:

    p = large prime
    q = prime divisor of p - 1
    g = generator
    x = private key
    y = public key

Private key range:

    1 <= x <= q - 1

Public key:

    y = g^x mod p

Message hash:

    H = Hash(message)

Choose a fresh secret per-signature value k:

    1 <= k <= q - 1

First signature component:

    r = (g^k mod p) mod q

Second signature component:

    s = k^(-1) * (H + x*r) mod q

Signature:

    (r, s)

Verification:

    w = s^(-1) mod q
    u1 = H*w mod q
    u2 = r*w mod q

    v = ((g^u1 * y^u2) mod p) mod q

The signature is valid if:

    v = r

The Python cryptography library performs the mathematical operations internally.

4. DEFINITIONS OF FORMULA SYMBOLS
---------------------------------
p and q:
Prime parameters.

g:
Generator.

x:
Private key.

y:
Public key.

H:
Message hash.

k:
Per-signature secret random value. It must be protected and never reused improperly.

r and s:
Two components of a DSA signature.

w, u1, u2, v:
Intermediate verification values.

mod:
Remainder after division.

5. CODE EXPLANATION
-------------------

from cryptography.hazmat.primitives.asymmetric import dsa
Imports DSA functionality.

from cryptography.hazmat.primitives import hashes
Imports hash algorithms.

from cryptography.exceptions import InvalidSignature
Imports the exception raised when signature verification fails.

private_key = dsa.generate_private_key(key_size=2048)
Generates a DSA private key with a 2048-bit parameter size.

public_key = private_key.public_key()
Extracts the matching public key.

message = b"Government Tender Submission: Amount 500000"
The b prefix creates a bytes object.

signature = private_key.sign(message, hashes.SHA256())
Signs the message with the private key and SHA-256.

signature.hex()
Displays the binary signature in hexadecimal form.

public_key.verify(signature, message, hashes.SHA256())
Checks the signature. If verification succeeds, the method returns normally. If it fails,
it raises InvalidSignature.

try:
    Runs code that may raise an exception.

except InvalidSignature:
    Handles an invalid signature.

modified_message:
The program's supplied modified_message is:
    b"Government Tender Submission: Amount 500000"

This is identical to the original message. Therefore verification of this so-called
modified message should succeed. To test tampering, change the amount, for example:
    b"Government Tender Submission: Amount 900000"

another_private_key = dsa.generate_private_key(key_size=2048)
Generates a different private key.

wrong_public_key = another_private_key.public_key()
Extracts the unrelated public key.

Verification with this wrong public key should fail.

7. VIVA QUESTIONS
-----------------
Q: What is DSA?
A: A public-key digital signature algorithm.

Q: Is DSA used for encryption?
A: No. It is used for signing and verification.

Q: Which key signs?
A: The private key.

Q: Which key verifies?
A: The corresponding public key.

Q: Why is SHA-256 used?
A: To hash the message as part of signature processing.

Q: What happens if the message changes?
A: Verification fails, provided the changed message differs from the signed message.

Q: What happens with the wrong public key?
A: Verification fails.

Q: What is non-repudiation?
A: Evidence that a particular key signed the message, assuming trustworthy key ownership
and control.

COMMON CRYPTOGRAPHY DEFINITIONS
============================================================

Symmetric cryptography:
Uses the same secret key for encryption and decryption.

Asymmetric cryptography:
Uses a related public key and private key.

Encryption:
Transforms readable data into ciphertext using an algorithm and key.

Decryption:
Recovers plaintext from ciphertext using the appropriate key.

Hashing:
Maps input data to a fixed-length digest.

Digital signature:
A value generated with a private key and checked with the public key.

Key exchange:
A process through which parties establish a shared secret.

Confidentiality:
Only authorized parties can read the information.

Integrity:
Unauthorized changes to data can be detected.

Authentication:
Verifies the identity or origin of a communication.

Non-repudiation:
Provides evidence of origin or signing, subject to secure key control and identity binding.

Plaintext:
Original readable information.

Ciphertext:
Encrypted information.

Nonce:
A value used once with a cryptographic key.

Salt:
Random data added to a password before password hashing.

Padding:
Extra structured data added to fit or secure a cryptographic operation.

Modulus:
The number by which a value is reduced in modular arithmetic.

Digest:
The output of a hash function.
