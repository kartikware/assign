ASSIGNMENT 5 - DIFFIE-HELLMAN KEY EXCHANGE WITH
             MAN-IN-THE-MIDDLE ATTACK
============================================================

1. AIM
------
To demonstrate normal Diffie-Hellman key exchange and show how a Man-in-the-Middle
(MITM) attacker can intercept and modify communication when public keys are not
authenticated.

2. DEFINITIONS
--------------
Diffie-Hellman:
A key-agreement method that allows two parties to derive a shared secret over a public
channel.

Private key:
A secret number chosen by a participant.

Public key:
A value calculated from the private key and shared with the other participant.

Shared secret:
A value independently calculated by both participants. Both should obtain the same value.

MITM:
Man-in-the-Middle. An attacker positions themselves between two communicating parties,
intercepts their public values and substitutes their own.

Generator:
A mathematical value g used in modular exponentiation.

Modular arithmetic:
Arithmetic where results are reduced by a modulus.

3. VALUES USED IN THE SUPPLIED PROGRAM
---------------------------------------
    p = 23
    g = 5

Private values:
    Alice private = 6
    Bob private   = 15
    Eve private 1 = 7
    Eve private 2 = 9

These are deliberately small demonstration values. They are not secure for real use.

4. MATHEMATICAL FORMULAS
------------------------

Alice public key:

    A = g^a mod p

Bob public key:

    B = g^b mod p

Alice's shared secret:

    K_A = B^a mod p

Bob's shared secret:

    K_B = A^b mod p

Because:

    (g^b)^a mod p = (g^a)^b mod p

Therefore:

    K_A = K_B = g^(ab) mod p

MITM case:

Eve creates two private values e1 and e2.

Eve public values:

    E1 = g^e1 mod p
    E2 = g^e2 mod p

Alice is made to use E2 instead of Bob's real public key:

    K_AE = E2^a mod p

Eve calculates the same Alice-Eve secret:

    K_EA = A^e2 mod p

Bob is made to use E1 instead of Alice's real public key:

    K_BE = E1^b mod p

Eve calculates the same Bob-Eve secret:

    K_EB = B^e1 mod p

Thus:

    K_AE = K_EA
    K_BE = K_EB

Eve can decrypt data from Alice and encrypt altered data for Bob.

5. CODE EXPLANATION
-------------------

p = 23
The modulus used in the demonstration.

g = 5
The generator used in modular exponentiation.

alice_private = 6
Alice's secret exponent.

def generate_public_key(private_key):
    return pow(g, private_key, p)

Calculates the public key.

pow(g, private_key, p)
Python's three-argument pow performs modular exponentiation:
    (g ** private_key) % p
It is more efficient than calculating the full power first.

def generate_shared_key(public_key, private_key):
    return pow(public_key, private_key, p)

Calculates the shared secret from the other party's public key and the local private key.

alice_public = generate_public_key(alice_private)
Calculates Alice's public key.

alice_key = generate_shared_key(bob_public, alice_private)
Alice calculates the shared secret using Bob's public key and Alice's private key.

bob_key = generate_shared_key(alice_public, bob_private)
Bob independently calculates the shared secret.

alice_key == bob_key
Checks whether both participants obtained the same secret.

Eve generates two public keys:
    eve_public_1
    eve_public_2

alice_received = eve_public_2
Alice receives Eve's substituted public key instead of Bob's.

bob_received = eve_public_1
Bob receives Eve's substituted public key instead of Alice's.

Eve calculates both shared keys and can read the communication.

6. MESSAGE ENCRYPTION IN THIS DEMONSTRATION
-------------------------------------------
def encrypt(message, key):
    return bytes(b ^ key for b in message.encode())

message.encode()
Converts the message to bytes.

for b in message.encode()
Loops through every message byte.

b ^ key
XORs each byte with the shared key.

bytes(...)
Collects the generated byte values into a bytes object.

8. SECURITY OBSERVATION
-----------------------
Normal Diffie-Hellman creates a matching shared secret, but plain unauthenticated
Diffie-Hellman does not prove who supplied the public key. An attacker can substitute
public values and create separate secrets with Alice and Bob.

Authentication, for example through certificates or authenticated key exchange, is
needed to prevent this attack.

The XOR message encryption in this program is only a demonstration and is not secure
modern message encryption.

9. VIVA QUESTIONS
-----------------
Q: What is Diffie-Hellman?
A: A key-agreement protocol for deriving a shared secret.

Q: Does Diffie-Hellman directly encrypt messages?
A: No. It establishes a shared secret that can be used by an encryption algorithm.

Q: Why do Alice and Bob get the same key?
A: Because modular exponentiation gives g^(ab) mod p from either side.

Q: What is MITM?
A: An attacker intercepts and substitutes communication between two parties.

Q: Why does MITM work here?
A: The public keys are not authenticated.

Q: What does pow(g, a, p) mean?
A: It calculates g raised to a, modulo p.

Q: How can MITM be prevented?
A: Authenticate public keys using certificates, signatures or an authenticated key exchange.

COMMON CRYPTOGRAPHY DEFINITIONS
============================================================

Symmetric cryptography:
Uses the same secret key for encryption and decryption.

Asymmetric cryptography:
Uses a related public key and private key.

Encryption:
Transforms readable data into ciphertext using an algorithm and key.

Decryption:
Recovers plaintext from ciphertext using the appropriate key.

Hashing:
Maps input data to a fixed-length digest.

Digital signature:
A value generated with a private key and checked with the public key.

Key exchange:
A process through which parties establish a shared secret.

Confidentiality:
Only authorized parties can read the information.

Integrity:
Unauthorized changes to data can be detected.

Authentication:
Verifies the identity or origin of a communication.

Non-repudiation:
Provides evidence of origin or signing, subject to secure key control and identity binding.

Plaintext:
Original readable information.

Ciphertext:
Encrypted information.

Nonce:
A value used once with a cryptographic key.

Salt:
Random data added to a password before password hashing.

Padding:
Extra structured data added to fit or secure a cryptographic operation.

Modulus:
The number by which a value is reduced in modular arithmetic.

Digest:
The output of a hash function.
